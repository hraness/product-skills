# Product skills

- This repository contains only public integration text and generated packages. Product application source stays in its owning repository.
- `catalog/admitted.json` records qualified sources; `bundles/` holds those validated public bundles. Change generated files through `node scripts/distribution.mjs reconcile`.
- Accept only exact identities in the validators: packages, listings and publications cover the four product origins in `PRODUCTS`, and the profile links add only the portfolio entries in `PROFILE_ONLY`. An identity is an id and its origin. A product's name is the product's own: take it from the portfolio or its bundle and never pin it, so a rename needs no change here. Preserve the last admitted package when a source, public runtime or guide fails qualification. Do not weaken a boundary to admit an unpublished release.
- Run `npm run check` with Node 24 before delivery. Tests use synthetic bundles, fake HTTP responses and deterministic archives; no signed-in browser or production user data is needed.
- Follow DOCUMENTATION_GUIDELINES.md, README_GUIDELINES.md, STYLE.md and WRITING.md. Root review owns public prose and publication decisions.
- Deliver task branches through protected pull requests and the required current-head check. Repository source updates and public store approvals are separate states.
- `publication-ledger.json` contains verified actual publications only. Preserve every existing entry; add records only after public listing or immutable release readback establishes the exact artifact identity.

<!-- hraness-ci:start -->
- CI exists to admit a change in minutes, not to perform a ceremony. Every workflow declares `concurrency: { group: <name>-${{ github.event_name == 'pull_request' && github.ref || github.sha }}, cancel-in-progress: ${{ github.event_name == 'pull_request' }} }`, so a new push supersedes a pull request's run but a later run never cancels one on `main` or a release commit (a rerun on `main` cancelled a release commit's gate in ghostget run 36521676149). That per-SHA group is for check and gate workflows only. Release and deploy workflows, and deploy or release jobs inside check workflows, keep a group without the commit SHA, such as `deploy-${{ github.ref }}` or one group per environment, with `cancel-in-progress: false`, so merges deploy one at a time in order and an older deploy never lands after a newer one. Every workflow also declares a `timeout-minutes` on every job, and `permissions: contents: read` at the top with job-level widening only where needed.
- One job named `Required` closes every check workflow: `if: always()`, `needs:` every blocking job, and a single step that fails unless each `needs.<job>.result == 'success'`, or `skipped` because the change filter below reported its inputs unchanged. Branch policy requires only `Required` (plus a provider's own automated admission status when the product depends on it). Never make CodeQL, scheduled, or advisory jobs required.
- Cache by lockfile hash and restore before install. Pull request runs only restore (`actions/cache/restore`); caches are saved only on `main` (`actions/cache/save` under `if: github.ref == 'refs/heads/main'`, `Swatinem/rust-cache@v2` with `save-if: ${{ github.ref == 'refs/heads/main' }}`, `astral-sh/setup-uv` with `save-cache` set the same way). A pull-request-scoped save is readable by no other pull request and evicts shared keys from the repository's 10 GiB cache. A repository whose CI runs only on pull requests adds a warm-cache job on push to `main` or on a schedule that restores and saves the shared keys. Use `oven-sh/setup-bun@v2` plus the restore/save pair on `~/.bun/install/cache` for Bun, and the pair instead of the `cache:` input of `actions/setup-node` or `actions/setup-python`, which also saves on pull requests. Playwright browsers are cached under `~/.cache/ms-playwright` keyed by the Playwright version.
- Rust: install the pinned toolchain with `dtolnay/rust-toolchain` (`rustup toolchain install` at most once per job, `--profile minimal`), set `CARGO_INCREMENTAL: 0`, `CARGO_TERM_COLOR: always`, `CARGO_NET_RETRY: 10`, `RUSTFLAGS: -D warnings` and `RUST_BACKTRACE: short` at workflow level, use `cargo nextest` or one `cargo test --workspace --locked` after a shared `cargo build --all-targets --locked`, run `clippy` and `fmt` once on Linux only, install tools with `taiki-e/install-action` or `cargo-binstall` instead of `cargo install`, and build release binaries in one job whose artifact every later job reuses. Never build the same crate twice in one workflow.
- Run the matrix Linux-first. A macOS or Windows job exists only when the product ships a native surface for that OS, runs the OS-specific tests only, and is never the only place a generic check runs. Split long serial script lists into parallel jobs that share one build artifact instead of one job that runs for twenty minutes.
- Skip work that cannot change the result inside the workflow: a change-detection job runs `dorny/paths-filter@v4` (it needs job permission `pull-requests: read`, and `predicate-quantifier: some-with-excludes` needs v4), and jobs whose inputs did not change skip through job-level `if:`. Never put `paths`, `paths-ignore`, or `branches-ignore` on the `pull_request` trigger of the workflow that produces `Required`: a skipped workflow never reports `Required`, and the pull request can never merge. Every `uses:` pins a major tag or a SHA with a version comment, and Dependabot keeps `github-actions` current weekly, grouped as in `templates/dependabot.yml` from hraness/.github. The daily PR sweep merges its patch and minor updates; it hands an update whose size Dependabot doesn't state, such as one for a SHA pinned without a version comment, to a Diocles task. Don't add a workflow that turns on auto-merge with `GITHUB_TOKEN`: merges made with that token start no workflow run on main.
- Private repositories pay for every job-minute; public ones run free. In a private repository, count billed job-minutes next to wall time: each job rounds up to a whole minute and repeats its own setup, so sharding that adds jobs is not a saving there. Run no macOS or Windows job without a native surface for that OS (mark it `# cost-lint: native-surface`), run trivial jobs such as change filters and `Required` on `ubuntu-slim`, gate every job `Required` does not need for the change through the change filter, and order jobs so the cheapest likely failure runs first. Dependabot runs weekly with grouped updates and `open-pull-requests-limit: 1`. `scripts/ci-cost-lint.py` in hraness/.github checks these rules.
- Measure before and after: a CI change records the previous and new median wall time of the slowest workflow in its pull request body. Regressions that add more than a minute to `Required` are reverted forward the same day.
